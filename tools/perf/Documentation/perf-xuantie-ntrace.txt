perf-xuantie-ntrace(1)
======================

NAME
----
perf-xuantie-ntrace - Support for XuanTie RISC-V Nexus Trace within
perf tools.

SYNOPSIS
--------
[verse]
'perf record' -e xuantie_ntrace//

DESCRIPTION
-----------

RISC-V N-Trace (Nexus-based tracing) is a debugging and tracing
technology for the RISC-V architecture. This technology defines a
trace encoder component and is built on the well-known Nexus
IEEE-ISTO 5001 standard. The RISC-V International Foundation has
established the N-Trace Working Group, which aims to leverage the
widely used and well-documented IEEE-ISTO 5001 Nexus tracing
standard as the basis for an equivalent solution for the RISC-V
architecture. This solution is specifically designed to support
tracing functionality for RISC-V ISA cores, Harts, and SoC/MCU
designs.

The design of XuanTie follows the RISC-V Nexus Trace design and
integrates it into the perf tool for user use. It primarily provides
program flow tracing and trace data parsing. It shows the execution
flow of user-space programs, including instruction stream information,
symbol information, executed file information, and some event changes
that occur during program execution, such as privilege mode changes,
interrupt generation, and scheduling events.

Trace data is collected by 'perf record' and stored within the
perf.data file.

Quickstart
----------

When using XuanTie N-Trace, we primarily use two commands, for
example, to collect the instruction stream of the "ls" command
executed in User-mode:

	perf record -e xuantie_ntrace//u ls

To display the collected instruction stream information, use:

	perf script

During the perf record process, support for privilege mode filtering
and address range filtering is provided.


Collect the entire execution process of "ls".

	perf record -e xuantie_ntrace// ls

Collect the instruction stream of "ls" execution that runs in
Supervisor-mode.

	perf record -e xuantie_ntrace//k ls

Collect the instruction stream of "ls" execution that runs in
User-mode.

	perf record -e xuantie_ntrace//u ls

During the execution of "ls", start collecting all instruction
streams when the program reaches the address 0x11223344.

	perf record -e xuantie_ntrace/start_addr=0x11223344/ ls

During the execution of "ls", start collecting all instruction streams
when the program reaches the address 0x3344 and stop collecting when
it reaches the address 0x7788.

	perf record -e xuantie_ntrace/start_addr=0x3344,stop_addr=0x7788/ ls

Privilege mode filtering and address range filtering can coexist.
During the execution of "ls", start collecting User-mode instruction
streams when the program reaches the address 0x3344 and stop
collecting when it reaches the address 0x7788.

	perf record -e xuantie_ntrace/start_addr=0x3344,stop_addr=0x7788/u ls


NOTE: Since a.out(like "ls") is scheduled by the kernel and runs
multiple times during its execution, the perf tool will configure the
trace module multiple times. This means that the Trace component is
disabled each time a.out is suspended and reconfigured when the
program is resumed. As a result, the data filtered by address may be
incomplete.


After generating the perf.data file, we primarily use the perf report
and perf script commands to analyze it.


For developers or those familiar with low-level details who want to
view the raw data stream generated by the Trace, they can use the
command below to check the display from parsing the Trace source data,
analyze the MSEO/MDO format, and reconstruct it into RISC-V N-Trace
Messages:

	perf report -D

RISC-V N-Trace Messages are the fundamental data. For general users,
what is more needed is the program execution flow reconstructed from
the Trace. At this point, "perf script" command is used.

For perf script, we might use several commands:

	perf script --itrace=n0/1/2/3/4/5

Parameters Detail:

	perf script --itrace=n0  // print start_addr, end_addr,
				 // symbols, dso_name and necessary
                                 // ntrace messages

	perf script --itrace=n1  // print start_addr, end_addr,
                                 // symbols, dso_name and all
                                 // ntrace messages

	perf script --itrace=n2  // print start_addr, end_addr,
                                 // symbols, dso_name, pc ranges
                                 // and necessary ntrace messages

	perf script --itrace=n3  // print start_addr, end_addr,
                                 // symbols, dso_name, pc ranges
                                 // and all ntrace messages

	perf script --itrace=n4  // print start_addr, end_addr,
                                 // symbols, dso_name, pc ranges,
                                 // instructions and necessary
				 // ntrace messages

	perf script --itrace=n5  // print start_addr, end_addr,
                                 // symbols, dso_name, pc ranges,
                                 // instructions and all
				 // ntrace messages

	"perf script" is equal to "perf script --itrace=n2"


NOTE: In perf script, we analyze the address ranges information between
Start_addr and End_addr for an N-Trace Message, as well as the
disassembly information of the instructions within these address ranges.
To obtain this information, perf needs to have access to the executed
binary files and must be capable of opening ELF files, which requires
LIBBFD configuration support. This means that if perf does not have
access to the executed binary files or if perf lacks libbfd support,
then even with the --itrace=n5 option, the disassembly information
will not be displayed.

NOTE: The following messages are printed depending on the level
selected via --itrace=n?.

. Messages starting with 'TCODE' are the raw RISC-V N-Trace messages,
  which are displayed when selecting 'all ntrace messages' in --itrace=n?
  or when using perf report -D.
. Messages starting with 'Start' will be printed in the perf script
  command:
  * 2.1 "0x285fc, _dl_aux_init, (/root/a.out)" refer to the PC
    (Program Counter), the function where the PC is located,
    and the file where the PC is located, respectively.
  * 2.2 "Start" refers to the beginning position of the instruction
    stream expressed by that message.
  * 2.3 "End" refers to the final position to which the instruction
    stream expressed by that message jumps.
. Messages starting with 'Include pc ranges:' are displayed when
  selecting 'pc ranges' in --itrace=n?. In these messages, the instruction
  at the PC address on the left has been executed, while the instruction
  at the address on the right has not been executed, and it is
  represented by 'PC-1'.
. Disassembly information like '285fc: ld a5,0(a0)' is displayed when
  selecting 'instructions' in --itrace=n?.
